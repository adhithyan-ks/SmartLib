\chapter{Testing and Test Cases}

\section{Manual Functional Testing Strategy}
Quality assurance for SmartLib was conducted through systematic \textbf{Black-Box Manual Functional Testing} performed directly through the application's Graphical User Interface (GUI). As beginner Java and Object-Oriented Programming students, our team validated the application by interacting with every screen exactly as end-users (librarians and students) would: typing inputs into text fields, choosing options from dropdown combo boxes, clicking action buttons, confirming modal dialogs, and verifying on-screen results.

\subsection{Testing Approach and Methodology}
The manual testing procedure followed a structured, repeatable sequence:
\begin{enumerate}
    \item \textbf{Action Execution:} Perform specific user interactions on the active Swing panels (e.g., submitting credentials on the login screen, registering a book, issuing a physical copy, or filtering tables).
    \item \textbf{UI Feedback Verification:} Observe and verify the visual feedback presented by the application, including informational message dialogs (\texttt{JOptionPane.showMessageDialog}), error alerts, and field-clearing behaviors.
    \item \textbf{State and Data Verification:} Confirm that table models (\texttt{JTable}) refresh immediately with updated records, that status badges reflect the correct state (e.g., \texttt{AVAILABLE} $\to$ \texttt{ISSUED}), and that dynamic calculations (such as days overdue and late fines) display accurate mathematical values.
    \item \textbf{Database Persistence Check:} Verify that completed transactions, new registrations, and status updates persist reliably in the underlying MySQL database across session logouts and application restarts.
\end{enumerate}

\subsection{Test Environment}
All manual test cases were executed in the following local environment:
\begin{itemize}
    \item \textbf{Operating System:} Linux (Ubuntu 24.04 LTS) / Windows 11
    \item \textbf{Java Runtime:} OpenJDK 17 LTS (Java SE 17)
    \item \textbf{Database:} MySQL Community Server 8.0 running locally on port \texttt{3306}
    \item \textbf{Initial Data State:} Populated with institutional seed records from \texttt{sample\_data.sql} (default librarian \texttt{admin}, sample books \texttt{B1001}--\texttt{B1003}, and enrolled students \texttt{TVE23CS001} and \texttt{TVE23CS002})
\end{itemize}

\section{Viva Voce Testing Notes and Demonstration Guide}
During project evaluations and viva voce examinations, our team can directly demonstrate the following practical test workflows:
\begin{enumerate}
    \item \textbf{Demonstrating Overdue Fines:} In the live database, sample book \texttt{B1003} is pre-seeded with a past due date (\texttt{2023-10-15}). In the Circulation Desk, selecting the ``Overdue'' filter instantly displays this record with calculated overdue days and fine accumulated at \rupee 10.00 per day.
    \item \textbf{Demonstrating Input Validation:} Typing lowercase or invalid KTU IDs triggers instant validation alerts, while typing a valid format auto-populates branch and batch.
    \item \textbf{Demonstrating Reservation Alert:} Returning an issued book with a pending reservation triggers a notification popup instructing the librarian to hold the book for the next student in the queue.
    \item \textbf{Demonstrating Data Safety:} Attempting to delete a student who has active or historical borrowing records is automatically blocked to preserve institutional audit trails.
\end{enumerate}
